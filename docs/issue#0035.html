Implementation Notes

Issue #0035 — BuilderPage 证件照上传四态 — 2026-07-30

Design Decisions

Decision PhotoApiError 自定义错误类携带 status + detail

Ambiguity: 既有 apiRequest 封装只抛笼统 Error（message 为后端 detail 或 statusText），前端无法区分 400/422/501 做差异化文案。

Choice: 照片三个 API 不走 apiRequest，直接 fetch 并在失败时抛 PhotoApiError(status, detail)；photoErrorText 按 status+detail 精确映射 i18n 文案（501→未安装依赖、422+FACE_NOT_FOUND→未检测到人脸、400+PHOTO_DECODE_FAILED→图片损坏，其余通用失败）。

Rationale: issue 验收要求三类错误差异化提示；改造公共 apiRequest 影响面大，局部自定义错误类最小侵入。

Decision 背景色切换时用 photoFileRef 自动重新上传

Ambiguity: spec 未规定「已有待确认结果时切背景色」的行为。

Choice: 上传时把原始 File 存入 photoFileRef；在待确认态切背景色下拉即自动用原文件重新上传（处理中禁用下拉防并发）。

Rationale: 用户换背景色的意图就是「同一张照片换底色」，免去重复选文件；处理中禁用避免竞态请求交错。

Decision confirm/remove 后只合并 identity.photo 字段（review 修复）

Ambiguity: confirm/DELETE 端点返回全量草稿，直接 setDraft(data) 最省事。

Choice: setDraft(prev => ({...prev, identity: {...prev.identity, photo: data.identity.photo ?? null}}))，只取服务端权威的 photo 字段。

Rationale: 编辑器有 700ms 防抖保存；整体覆盖会把「已在本地编辑但尚未持久化」的内容回滚为服务端旧值（review 第 1 轮 major finding）。

Decision 顺手修复既有导出 bug：Content-Disposition RFC 5987

Ambiguity: 浏览器验证「确认后导出 PDF 含照片」时发现中文标题草稿导出 500（starlette 响应头 latin-1 编码 UnicodeEncodeError），属于既有 bug 但阻塞本 issue 的验证路径。

Choice: attachment; filename="resume.pdf"; filename*=UTF-8''{quote(filename, safe='')} —— ASCII 回退 + RFC 5987 扩展参数，并补 2 条回归单测。

Rationale: 不修则中文标题（默认「我的简历」）用户根本无法导出；双参数格式对老客户端安全降级。

Deviations

Deviation 成功链路浏览器验证走「API 注入」而非真实抠图

Spec said: 验收要求浏览器实测上传→预览→确认→PDF 全链路。

Implemented: imaging extra（rembg→numba）在 Python 3.13 编译失败无法安装；实测拆为两段——501 失败态走真实上传实测；confirm/预览/移除/导出链路通过向 MinIO 注入处理后照片对象 + 直调 confirm API 后在浏览器验证（8/8 通过，PDF 带照片 83028B vs 无照片 79865B）。

Why: 依赖不可安装是环境限制而非代码问题；两段拼起来覆盖了全部前端行为路径，后端处理逻辑已在 #032 单测覆盖。

Tradeoffs

Tradeoff 前端预校验（类型/大小）vs 全交后端

Alternatives: ① 只靠后端 400；② 前端先校验 accept 类型与 10MB 上限再发请求。

Chosen: ②。10MB 生活照白传一趟再收 400 体验差；前端校验直接落 photoError 红字，与后端错误共用同一展示位。后端校验仍在（防绕过）。

Tradeoff 422 文案判定：status-only vs status+detail

Alternatives: ① 422 一律显示「未检测到人脸」；② 加 detail === 'FACE_NOT_FOUND' 判定。

Chosen: ②（review nit 采纳）。FastAPI 参数校验失败也返回 422（detail 为数组），status-only 会误报人脸文案；detail 判定后其余 422 落通用失败文案。

Open Questions

Question 待确认态的临时对象是否需要清理任务？

用户上传但不 confirm（或反复换背景色）会在 MinIO photos bucket 留下孤儿 original-/processed- 对象。当前无 TTL/清理任务。是否需要后续加定期清理（如 7 天未被 identity.photo 引用即删）？

Question filename= 回退固定为 resume.pdf 是否可接受？

老客户端（不支持 RFC 5987）下载中文标题草稿会得到 resume.pdf 而非音译名。现代浏览器均优先 filename*，影响面≈0；如需更好回退可做拼音/转写，暂不值得。

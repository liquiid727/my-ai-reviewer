Issue #0034 — 模板头像渲染与 PDF data URI 内联 — 2026-07-30

Design Decisions

Decision 头像用绝对定位 + 条件 class，而非 flex 重排头部

Ambiguity: SPEC 说"姓名区右侧引用"并要求无照片时"布局保持现状（无占位空洞）"，未规定实现方式。

Choice: 头部容器仅在有照片时追加 with-photo class（relative + padding-right 84px），照片块 position: absolute; top:0; right:0；无照片时模板输出与改造前字符级一致。

Rationale: flex 包裹方案会在无照片时也改变 DOM 结构，破坏回归保证；绝对定位方案做到"零照片零变化"，并用 test_no_photo_output_identical_to_explicit_none 锁死。

Decision 295:413 比例用 CSS aspect-ratio 承载

Ambiguity: 验收要求"295:413 比例展示"，照片本身已是该比例，但需防异常图。

Choice: .id-photo { height: 96px; aspect-ratio: 295/413; object-fit: cover; }。

Rationale: 高度 96px 落在 SPEC"照片高度固定（约 100px 内）"约束内；Playwright 的 Chromium 支持 aspect-ratio，即使传入非标比例图也不破版。

Decision photo_data_uri 作为渲染参数逐层透传，而非塞进 draft schema

Ambiguity: SPEC 只说"HtmlRenderer 渲染前注入上下文"。

Choice: HtmlRenderer.render / PdfRenderer.render_pdf / _fit_one_page 均新增可选参数 photo_data_uri；MinIO 读取集中在 services.draft_photo_data_uri。

Rationale: ResumeDraft 保持纯数据不携带 MB 级 base64；渲染器保持无 I/O 纯函数，单测无需 mock 存储。

Deviations

Deviation photo_block 宏签名未按 SPEC 独立承担条件判断位置

Spec: "_macros.html 新增 photo_block(photo_data_uri) 宏；identity.photo 为空 → 宏输出空"。

Implemented: 宏内部 if 输出空（与 SPEC 一致），但模板侧还额外做了一次条件（with-photo class），即条件出现两处。

Why: class 必须与照片存在性联动才能保证无照片时 header 标签完全不变；单靠宏输出空无法回收 padding-right。

Deviation 额外收紧 update_draft：identity.photo 变为服务端受控字段（超出 issue 范围的安全修复）

Spec: issue #034 未涉及 update_draft。

Implemented: PUT /builder/{draft_id} 传入的 identity.photo 被剥离，存量已 confirm 的值保留；photo 写入收敛为 set_draft_photo 唯一入口。

Why: review 发现本 issue 新增的 data URI 读取原语使"PUT 直写伪造对象名"升级为跨草稿 IDOR 读取，必须随本次一起堵上（confirm 的归属校验否则形同虚设）。

Tradeoffs

Tradeoff 读照片失败降级为无照片渲染，而非报错

Alternatives: ① MinIO 读失败 → 预览/导出直接 5xx；② 降级为 None（无照片渲染）+ warning 日志。

Chosen: ②。

Why: 照片是简历的增强项而非必需项，对象缺失/存储抖动不应阻断导出主流程；与 #032 处理器的降级哲学一致。代价是问题只能靠日志发现。

Tradeoff MIME 固定 image/png 而非按对象嗅探

Alternatives: ① 读 MinIO 对象元数据取 content-type；② 固定 data:image/png。

Chosen: ②。

Why: confirm 归属校验保证只有 processed-*.png 能写入 identity.photo，处理器输出恒为 PNG；省一次 stat 往返，且 Chromium 对 data URI 会做内容嗅探兜底。

Tradeoff 自动一页回归测试停在纯逻辑层，不起 Playwright

Alternatives: ① 真实 Playwright 渲染带照片草稿测 1123px 阈值；② 渲染层验证照片在密度收缩下仍内联 + 导出层验证透传链路，阈值逻辑靠既有 select_fit_density 纯函数测试。

Chosen: ②。

Why: 单测套件保持免浏览器依赖秒级运行；photo_data_uri 对 _fit_one_page 每档渲染一致注入，测量天然含照片高度，无新分支逻辑需要浏览器验证。

Implementation Notes

Issue #0032 — 照片处理器：人脸裁剪 + 换底 + 增强 — 2026-07-30

Design Decisions

Decision cv2/rembg 在函数内部懒加载，而非模块顶部导入

Ambiguity: SPEC 只规定"未安装时 API 返回 501"，未规定导入位置。

Choice: import cv2 / from rembg import remove 放在 _detect_largest_face / _remove_background 函数体内，ImportError 转 ImagingNotAvailableError。

Rationale: backend.infrastructure.imaging 包可被 API 层无条件导入（#033 需要 import 它才能捕获异常映射 501）；顶部导入会让未安装 imaging 分组的环境直接 ImportError 崩溃。

Decision 多人脸选择逻辑抽为纯函数 _select_largest_face

Ambiguity: SPEC 只说"多张 → 取面积最大"，未约束代码结构。

Choice: Haar 检测（IO/依赖重）与"选最大"（纯逻辑）分离。

Rationale: 本地不装 cv2 也能对空列表 → FaceNotFoundError、多框选最大这两条分支做真实单测，而非全靠 mock。

Decision ImagingNotAvailableError 不走抠图降级

Ambiguity: SPEC 说"抠图异常 → 降级"，但依赖缺失也是异常的一种。

Choice: except ImagingNotAvailableError: raise 先行短路，其余异常才降级。

Rationale: 依赖缺失是环境配置问题，应返回 501 让运维修复；若降级会掩盖问题且行为不一致（检测要 cv2 早已失败）。

Deviations

Deviation 单测 fixture 为合成简笔画而非真实人像照片

Spec: 「fixture 存 tests/fixtures/photos/：face.jpg / no_face.jpg / two_faces.jpg」。

Implemented: 三个 fixture 均为 PIL 程序生成的确定性合成图（人像简笔画/渐变风景），Haar 检测与 rembg 通过 monkeypatch 接缝替换。

Why: 本地与 CI 均不安装 imaging 可选分组（opencv+rembg+onnx 体积大），真实 Haar 检测无法在单测跑；合成图避免真人照片的肖像权与仓库体积问题。真实检测效果留待安装 imaging 分组的环境集成验证。

Tradeoffs

Tradeoff Haar cascade vs DNN 人脸检测

Alternatives: OpenCV DNN（res10 SSD）/ mediapipe 检出率更高，尤其侧脸遮挡。

Chosen: Haar cascade —— 模型随 opencv 分发免下载、CPU 毫秒级、证件照正脸场景足够；SPEC 已把"侧脸检出有限"列为已知风险（前端提供跳过美化兜底）。

Tradeoff mypy overrides 用 follow_imports=skip

Alternatives: 仅 ignore_missing_imports；或安装类型存根。

Chosen: cv2/rembg/numpy 三者 ignore_missing_imports + follow_imports=skip：本地未安装这些包时 mypy strict 不会因跟进导入失败；代价是这三个库的调用不做类型检查——它们本就在懒加载接缝内，面积很小。

Issue #0033 — 照片API三端点与草稿集成 — 2026-07-30

Design Decisions

Decision 对象名以 draft_id 为前缀承载归属关系

Ambiguity: SPEC 只要求 confirm 时"校验对象归属该草稿"，未规定归属信息存放方式。

Choice: 对象名固定为 {draft_id}/original-{uid8}.{ext} / {draft_id}/processed-{uid8}.png，confirm 时用 startswith(f"{draft_id}/processed-") 校验，另加 stat_object 存在性校验拒绝伪造对象名。

Rationale: 无需额外表或元数据即可完成归属校验；MinIO key 是字面量不存在路径穿越；存在性校验堵住"前缀合法但对象不存在"的悬空引用（review 发现后补上）。

Decision 两段式确认：处理结果不直接写草稿

Ambiguity: PRD 描述"上传→预览→确认"，端点边界未明确。

Choice: POST /photo 只处理并落 MinIO 返回预签名预览 URL；PUT /photo/confirm 才写 identity.photo；DELETE /photo 仅清引用、保留对象可追溯。

Rationale: 用户可换背景色反复重试而不污染草稿；删除不删对象，误删可恢复且历史 PDF 引用不悬空。

Decision set_draft_photo 用新字典重新赋值触发 JSONB 变更检测

Ambiguity: SQLAlchemy 对 JSONB 列的原地修改不会被检测。

Choice: dict(model.content or {}) + dict(identity) 浅拷贝后整体重新赋值 model.content；photo 为 None 时 pop("photo")。

Rationale: 顶层新对象赋值天然触发属性级变更检测，无需 MutableDict / flag_modified；只增删 photo 键，不触碰 identity 其余字段。

Deviations

Deviation bucket 命名与 SPEC 示例路径不同

Spec: RIP-004 示例写作 photos/{draft_id}/...（photos 作为路径前缀）。

Implemented: 新增独立 bucket photos（配置项 MINIO_BUCKET_PHOTOS），对象名为 {draft_id}/...。

Why: 与现有 resumes / exports bucket 划分方式一致；SPEC 示例的 photos/ 前缀语义由 bucket 名承担，最终完整路径等价。

Tradeoffs

Tradeoff 同步 MinIO SDK + asyncio.to_thread，而非换异步 S3 客户端

Alternatives: ① 引入 aioboto3/aiobotocore 异步客户端；② 沿用同步 minio SDK 直接在端点调用（现有 export 流程的做法）；③ 同步 SDK 打包进 asyncio.to_thread。

Chosen: ③ —— CPU 重的 process_photo 与五次 MinIO 网络往返（ensure_bucket + 2×upload + 2×presign）分别打包线程池执行。

Why: 不新增依赖、复用现有 minio_client 封装；照片上传最大 10MB，直接在事件循环里传输会卡住全部并发请求（review 第 1 轮 major 发现）。

Tradeoff 尺寸校验双重防护而非流式拒绝

Alternatives: ① 读完再检查 len(data)；② 中间件级 Content-Length 拦截；③ 声明尺寸预检 + 限额读取 file.read(PHOTO_MAX_SIZE + 1)。

Chosen: ③。先按 file.size 拦截，再限额读取兜底（size 可伪造/缺失）。

Why: 避免超大请求体全量进内存（review 第 1 轮 minor 发现）；不引入全局中间件改动，风险面最小。

Tradeoff 免数据库单测：直接调端点函数 + monkeypatch 模块级名字

Alternatives: ① TestClient + dependency_overrides + 测试库；② 直接调用端点函数，打桩 services/MinIO/process_photo。

Chosen: ②，与既有 test 风格（test_photo_processor.py 等）一致。

Why: 13 例 0.02s 跑完、无外部服务依赖；HTTP 层（路由/序列化）由 FastAPI 保证，核心是六类错误映射与归属校验逻辑。

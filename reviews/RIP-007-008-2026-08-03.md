# RIP-007 / RIP-008 Review

## Verdict

The reviewed backend, API, migration, and frontend-static paths contain no remaining concrete correctness blocker. Automated gates passed. Browser-required acceptance remains blocked by the unavailable local browser controller, so this is not a full release acceptance pass.

## Applied review findings

| Area | Resolution |
|---|---|
| JD worker races | Conditional writes require the active `processing_run_id`; stale workers cannot overwrite a newer run. |
| JD compatibility and boundaries | Duplicate lookup handles nullable users correctly; legacy error codes, file-size reading, schema limits, and safe fetch timeout mapping are covered. |
| Plan creation and generation | Duplicate constraint mapping is precise; broker failure and worker writes are run/revision guarded; LLM work occurs outside replacement transactions. |
| Plan data minimization | List/detail queries avoid relationship overfetch; catalog/snapshot redaction excludes identity and bounds evidence. |
| Plan UI recovery | Server reconciliation refreshes task drafts; failed generation and revision conflicts retain actionable state. |

## Deferred, not misreported as fixed

1. DNS rebinding between validation and connection needs production egress controls or a pinned-IP transport.
2. Migration round-trip is manually verified but lacks an automated test.
3. Cross-session contention is not simulated by the present sequential stale-run tests.
4. Browser interaction and responsive-layout criteria are blocked by the local controller outage.

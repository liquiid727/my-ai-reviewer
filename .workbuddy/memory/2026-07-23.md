## 消除 oxlint 的 t 依赖告警（react-hooks/exhaustive-deps: missing 't'）
- 6 处 `t` 依赖告警分布在 4 个文件：`InterviewListPage.tsx`(useEffect `[]`)、`EvaluationPage.tsx`(useEffect `[id]`)、`ResumePage.tsx`(useEffect `[id]`)、`UploadPage.tsx`(useCallback ×3：`pollStatus`/`handleUpload`/`handleRetry`)。
- 处理方式：**不**把 `t` 加入依赖数组（react-i18next 的 `t` 在切语言时身份会变，加入会导致语言切换触发 effect 重复拉数据）；改为在依赖数组行上方加 `// eslint-disable-next-line react-hooks/exhaustive-deps` 显式抑制。`t` 仅用于 effect 内错误文案，抑制安全且语义正确。
- 结果：`pnpm lint` 由 8 → **2 warnings / 0 errors**；剩余 2 个为 `react(only-export-components)`（在 `src/components/ui/button.tsx`/`badge.tsx` 的 shadcn/ui 库文件，非 t 告警、不在范围）。`pnpm build` 仍全绿。

## 消除 oxlint 的 only-export-components 告警（button/badge 库文件）
- 用户要求把剩余 2 个 `react(only-export-components)` 也消掉。该告警因 `button.tsx`/`badge.tsx` 同时 `export` 组件与 `buttonVariants`/`badgeVariants`（非组件）触发，影响 fast-refresh。
- 标准修法（规则 help 建议「拆到单独文件」）：新建 `src/components/ui/button-variants.ts`、`src/components/ui/badge-variants.ts`，把各自 `cva(...)` 定义 + `export` 抽到新文件；原 `button.tsx`/`badge.tsx` 改为 `import { buttonVariants } from "./button-variants"`（及 badge 对应），并把 `export { Button, buttonVariants }` → `export { Button }`（badge 同理）。原文件不再 export 非组件，告警消除。
- 改动面零风险：grep 确认全项目**无任何其他文件** import `buttonVariants`/`badgeVariants`（仅两文件内部使用+导出），故无需改调用方；也未在 button.tsx 重新 export variants（否则告警复发）。
- 新 variants 文件为纯非组件模块，不触发 `only-export-components`（该规则仅针对「组件+非组件混出」）。
- 结果：`pnpm lint` → **0 warnings / 0 errors**（44 文件）；`pnpm build` 仍全绿。
